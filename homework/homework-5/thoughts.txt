The most surprising thing about this homework was how much the failure mode shifted depending on the model size. With Qwen 3B, the tools worked fine — DuckDuckGo returned the right URLs, the custom schedule fetcher pulled the right HTML — but the model couldn't act on what it had. It would find "Paul Liang" in a search snippet and then say it didn't have enough information. Switching to gpt-4o-mini fixed most of this instantly, which made me think the bottleneck in a lot of agent systems isn't the tool design at all, it's the reasoning capacity of the model sitting in the middle.

The vision comparison was the most interesting part. I expected vision to help with text extraction — like being able to read a page better than ctrl+f — but it turned out the real win was layout understanding. The instructor names were rendered as styled cards that weren't easily searchable with text tools. Version B saw the card layout in one screenshot and extracted all four names in a single step. Version A spent 15 steps scrolling and searching and gave up. The token cost is brutal though — 28k tokens per screenshot adds up fast, and for T3 (finding a sentence with "2021") vision didn't help much because it's fundamentally a text extraction problem, not a layout problem.

The safety evaluation was a bit unsettling. Before adding the hardened prompt, the agent just... complied. It scraped real faculty emails from the course website and wrote a full impersonation email signed as Professor Bertsimas. The fix was straightforward (explicit refusal categories in the system prompt), but it made me think about how easy it is to deploy a capable agent without thinking carefully about what it will do when asked to do something it shouldn't.

The Discord deployment was more fun than I expected. The bot answered "is there a final exam?" correctly by reasoning from the schedule — there's no exam listed, but there are project presentations on 5/12. That's a question it wasn't explicitly trained to answer, and it got it right from first principles. That felt like actual agent behavior, not just retrieval.

One thing I kept running into: CodeAgent is not the right framework for a conversational assistant. It expects every output to be a code block, which means whenever the model wants to refuse or give a plain-text answer, it loops on parse errors until hitting max steps. ToolCallingAgent would have been better throughout. That's a lesson I'll carry forward for EgoBlind-RA — pick the agent class that matches the output type you actually want.
